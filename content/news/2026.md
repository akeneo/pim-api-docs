## November 2026

### <span class="label label-news label-updated">UPDATED</span> <span class="label label-news label-notice">NOTICE</span> New operators to search assets
**⚠️ This update could impact existing integrations.**

The [asset list search](/api-reference.html#get_assets) gets new operators and runs filters that used to fail:
- `!=` on text, number, boolean and date attributes, and on the `updated` and `created` dates. It only returns the assets that have a value.
- `NOT IN` on single option, multiple options and auto-tagging attributes.
- `=`, `!=` and dates without time on the `updated` filter at the root of the query.
- `=` on the `code` filter inside the `and` and `or` logical operators.
- The `complete` filter, with its required `channel` and `locales` properties.

The documentation now also covers the `created` filter, the `IN` operator on text attributes, and the operators allowed for each attribute type.

An operator that an attribute type or a field can't run, a filter on a media file or media link attribute, and more than 100 items in an `and` or `or` now return a `422` error that names the filter. Before, some of these searches returned no asset without any error: check your search queries against the supported operators.

👉 Learn more about [how to filter assets](/documentation/filter.html#filter-assets) and [how to use logical operators](/documentation/assets-filter-logical-operators.html)
